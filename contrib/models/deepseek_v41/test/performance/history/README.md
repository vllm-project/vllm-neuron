# Bench history: every `run_bench.py` run of this port

All runs on trn3.48xlarge (64 logical cores at LNC=2), checkpoint `/mnt/nvme/hf`, 128 output tokens,
medians. `max_num_seqs` is the engine's (`DEEPSEEK_V41_MAX_NUM_SEQS`; before 2026-10-24 every
engine above one rank was clamped to 1, and a `bs10` cell on such an engine queues its ten requests).
The top-level `bench_report*.json` files are the current reference per scheme; `history/reports/`
keeps the intermediate runs and `history/logs/` the console output of every run (its
summary table is at the end of each log). `cells/` holds the raw per-cell output of the last run
of each cell -- since 2026-10-30 13:34 all eight from r4_24 / r4_25 (tp64, greedy), with the server logs;
each cell's `generated_texts` holds its outputs.

**Input.** From 2026-10-25 (r3_19 on) the matrix is sonnet verse (`--dataset-name sonnet`), real
English at an approximate length; before that it was random token ids, on which the drafter accepts
far less (see `../README.md`), so earlier throughput rows are not comparable with later ones.
Since r4_01 every run is two invocations, batch 1 on one-sequence engines and batch 10 on
ten-sequence ones; `../README.md` ("Reproducing the reported numbers") has the commands.

Per cell: TPOT p50 / decode tok/s / vLLM draft acceptance.

**Temperature.** Until 2026-10-25 `run_bench.py` sent temperature 0 (greedy) to cells
on a one-sequence engine but **no temperature** to cells on a multi-sequence engine
(`max_num_seqs=10`), so the server sampled those at its default 1.0 -- through the
plugin's vocab-parallel sampler, which drew only from rank 0's 2048-token vocabulary
shard (letter-split text, 23-38% acceptance). Every `max_num_seqs=10` row before r3_19
is such a run. Since r3_19 every cell is greedy, and the model samples temperature
requests from the full vocabulary itself.
